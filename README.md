# 기록장 · 읽고 남은 것들

혼자 오래 쓰는 독서 기록장입니다. 크림색 종이와 녹색 잉크 톤의 반응형 화면으로, 책·문장·질문과 답·생각·여행을 보관합니다.

## 실행

Node.js 20 이상에서 폴더를 열고 실행합니다. 별도 패키지 설치는 필요 없습니다.

```sh
npm start
```

http://127.0.0.1:4173 에 접속합니다. HTML 파일을 더블클릭하는 방식은 모듈·IndexedDB·오프라인 기능을 지원하지 않으므로 사용하지 않습니다.

GitHub Pages에는 `index.html`, `src/`, `sw.js`, `manifest.json`, `icon.svg`, `icon-192.png`, `icon-512.png`을 같은 구조로 배포합니다. 이번 변경은 로컬 파일에만 적용했으며 원격 저장소에 푸시하거나 사이트를 배포하지 않았습니다.

## 구현한 기능

- 책장: 책 추가·수정·삭제, 읽는 중·완독, 책 제목·저자·문장·질문·답변 검색
- 표지: 실제 사진 업로드(JPG/PNG/WebP), 긴 변 800px로 축소, 글자 표지와 4가지 색상
- 도서 검색: 기본 Open Library 검색, 결과 선택으로 제목·저자·표지 입력
- 문장: 본문·페이지·내 생각, 수정·삭제 취소
- 질문: 질문과 답을 따로 저장, 책별 보기 및 모든 책의 미답변 질문 모아보기
- 생각·여행: 이전 기록을 유지하며 추가·수정·삭제
- 보관: IndexedDB, 전체 JSON 백업·복원, 직전 저장 상태 복구, 다른 창의 동시 저장 충돌 방지
- 초안: 문장·질문·답·책 정보의 텍스트 초안을 현재 탭의 sessionStorage에 보관. 사진과 표지 색상은 초안에 포함하지 않습니다.
- 오프라인: 온라인에서 한 번 로딩해 앱 캐시를 준비한 후 새로고침·조회·입력 가능

## 기존 기록은 어떻게 옮겨지나요?

같은 사이트 주소·브라우저에서 첫 실행 시 `onemonth_v1`의 기존 데이터를 새 IndexedDB `reading-notebook-v2`로 옮깁니다. 기존 localStorage는 수정하지 않으며 원본 문자열도 새 DB에 별도로 보관합니다.

기존 책·문장·생각·여행을 모두 가져오고, 기록마다 고유 ID를 부여합니다. 이전 `8/1` 날짜는 연도를 추측하지 않고 `이전 기록`으로 표시합니다. 새 기록은 연도를 포함한 시각을 저장합니다.

**로컬 미리보기와 GitHub Pages는 다른 저장소입니다.** 실제 사용 기록을 미리보기로 옮기려면 원래 앱에서 JSON을 내보낸 뒤 새 앱 보관함에서 가져오세요. 테스트용 브라우저 데이터는 사용자의 기록에 영향을 주지 않습니다.

`legacy-records.html`에는 변경 전 실제 앱 코드를 보관했습니다. 새 앱과 구 앱은 저장소가 달라, 구 앱에서 이후 작성한 내용은 새 앱에 자동 합쳐지지 않습니다.

## 백업과 복원

보관함 → 전체 기록 내보내기. 직접 올린 표지는 백업에 포함됩니다. 검색 표지는 원격 이미지 주소가 저장되므로 오프라인 표시와 이미지의 영구 제공을 보장하지 않습니다. 오래 보관할 표지는 직접 사진으로 넣을 수 있습니다.

복원은 JSON 전체를 검증하고 건수를 미리 보여준 뒤 적용합니다. 사용자가 교체 버튼을 누르면 현재 상태의 백업 다운로드를 시작하고, 하나의 DB 트랜잭션으로 교체합니다. 직전 저장 상태도 별도로 남습니다. 잘못된 파일이나 다른 탭과의 충돌은 기존 데이터를 바꾸지 않습니다. 브라우저가 다운로드를 차단했다면 별도로 내보내기 파일이 저장됐는지 확인하세요.

삭제 취소는 20초간 표시됩니다. 이후에는 다음 저장이 발생하기 전까지 보관함의 직전 저장 상태로 복구할 수 있습니다. 휴지통 전체 이력은 제공하지 않습니다.

브라우저 데이터 삭제·기기 변경에 대비해 별도 파일 백업이 필요합니다. 기기 간 자동 동기화·로그인은 구현하지 않았습니다.

## 국내 책 검색 연결

기본 검색은 키 없이 사용할 수 있는 Open Library입니다. 국내 책이나 특정 번역·판본이 없을 수 있으며 제목 검색은 작품 단위의 대표 표지를 반환할 수 있습니다. 제목·저자·표지를 직접 확인하고 선택하세요. 결과가 없거나 사진을 못 읽으면 직접 입력과 글자 표지로 계속 사용할 수 있습니다.

국내 도서는 카카오 책 검색을 씁니다. 이미 연결되어 있습니다.

중계소(Cloudflare Worker)가 카카오 열쇠를 들고 대신 물어봅니다. 열쇠는 앱에도 Git에도 들어가지 않습니다.

```
폰(기록장)  →  중계소  →  카카오
```

- 중계소 코드: `worker/book-search.js`
- 설치 순서: `worker/README.md`
- 앱이 부르는 주소: `src/config.js`의 `BOOK_SEARCH_ENDPOINT`
- 열쇠는 Cloudflare의 Secret(`KAKAO_KEY`)에만 있습니다

허용할 사이트 주소는 `worker/book-search.js` 위쪽 `ALLOWED` 목록에 있습니다. 앱 주소가 바뀌면 여기를 고치고 다시 Deploy 하세요.

검색이 연결되지 않은 상태에서는 키 없이 쓰는 Open Library로 자동 대체됩니다. 국내 책은 없거나 다른 판본일 수 있습니다.

로컬에서는 환경 변수 `KAKAO_REST_API_KEY`를 설정하면 `/api/books`로 자동 전환됩니다.

외부 전송: 검색어는 선택한 도서 검색 서비스로, 표지 표시 요청은 해당 이미지 제공자로 전달됩니다. 본문 기록은 서버로 보내지 않습니다. 온라인 글꼴은 Google Fonts를 요청하며, 오프라인에서는 기기 글꼴로 표시합니다.

공식 참고: [Open Library 검색](https://openlibrary.org/dev/docs/api/search), [표지](https://openlibrary.org/dev/docs/api/covers), [카카오 책 검색](https://developers.kakao.com/docs/ko/daum-search/dev-guide#search-book).

## 코드 구조

- `src/core.js`: 버전별 데이터 검증·이전·검색·백업 형식
- `src/storage.js`: IndexedDB 트랜잭션, 직전 상태, 동시 저장 충돌 검사
- `src/app.js`: 화면·입력·사진 처리·검색
- `src/style.css`: 데스크톱·모바일 디자인
- `server/`: 로컬 실행 및 선택적 카카오 API 연결
- `design/`: 기존 Claude 디자인 시안. 앱 실행 코드가 아닙니다.

예전 디자인 문서의 '인터넷 검색을 쓰지 않는다'는 조건은 실제 표지 검색을 요청한 현재 요구로 대체합니다. 새로운 기능 기준은 이 README입니다. OCR, 클라우드 동기화, 통계는 이번 구현 범위에 포함하지 않았습니다.

## 검증

```sh
npm test
```

데이터 이전, 잘못된 백업 거부, 사진 포함 백업 왕복, ID 중복 검사, 날짜·검색을 검사합니다.

브라우저 검증은 Playwright와 Microsoft Edge가 설치된 환경에서 서버 실행 후 수행합니다. Playwright가 별도 경로에 있으면 `NODE_PATH`에 해당 node_modules 경로를 지정합니다.

```sh
node tests/browser.cjs
node tests/storage-browser.cjs
node tests/search-browser.cjs
node tests/live-search.cjs
```

`browser.cjs`는 실제 UI에서 기존 기록 이전, 문장 CRUD·초안·삭제 취소, 질문·답, 사진 저장, 백업·복원, 모바일 너비, 오프라인 새로고침·저장을 확인합니다. `storage-browser.cjs`는 동시 저장 충돌과 실패 시 데이터 보존을 확인합니다. `search-browser.cjs`는 고정된 테스트 응답으로 검색 UI를 검사하고, `live-search.cjs`는 네트워크가 허용된 환경에서 실제 검색과 표지 이미지를 확인합니다.
